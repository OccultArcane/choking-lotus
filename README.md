# Choking Lotus

Single-screen launch page for **Choking Lotus**, an IMVU atelier. A chrome lotus sits at the centre of a liquid ripple, and the store's newest products orbit it as translucent cards. No scrolling, no sections — just the emblem, the drop, the legal line and a typing credit.

**Live (Freebuff):** https://site-65cbd85114804424ab593402b137206b.freebuff.page
**Live (GitHub Pages):** https://occultarcane.github.io/choking-lotus/

## Files

| Path | What it is |
| --- | --- |
| `index.html` | The whole page: backdrop layers, friends row, orbit markup, Instagram mark, legal strip, credit notice. |
| `css/style.css` | Every rule the page uses — backdrop, orbit mechanics, cards, fluid sizing, reduced-motion handling. |
| `js/main.js` | Builds the orbit cards, runs the cursor/parallax atmosphere and types the credit notice. |
| `js/products.js` | The store's newest eight products (titles, thumbnails, prices), generated by `tools/fetch_products.py`. |
| `assets/` | `lotus.webp`, `liquid-swirl.webp`, the product thumbnails and the `friends/` portraits. |
| `footer-note.txt` | Text typed into the popup. Edit this file to change the message; no code change needed. |
| `sites/` | Deploy glue: build script, manifest, asset worker with the two data routes, wrangler config. |
| `tools/refresh_friends.py` | Pulls the friends' current display names, shop links and portraits from IMVU. |
| `tools/fetch_products.py` | Rebuilds the product snapshot and its thumbnails from the store's newest listing. |

## Products

The orbit shows the store's eight newest products. On the Freebuff deployment `sites/worker.js` answers a same-origin `GET /api/products` route that reads the store's newest-first listing on the server (cached for five minutes, since the browser cannot fetch the listing itself), and `js/main.js` applies the result on load. The parsed listing is cached for five minutes in D1 (the `LISTING_DB` binding) and in a per-isolate copy in front of it, so repeat requests read one shared row instead of the store — roughly 0.4s from D1, or 0.08s from a warm isolate, against about a second upstream. The Cache API is not available to this deployment (`caches.default` answers "not permitted"), which is why D1 is used; the response's cache header covers repeat loads in the same browser. A new drop therefore appears without a redeploy. If the listing cannot be fetched, the route serves the committed snapshot from `assets/products/snapshot.json` instead — with a one-minute cache, so it returns to the live listing quickly. GitHub Pages has no such route, so it shows the snapshot committed in `js/products.js`.

The scheduled job rebuilds that snapshot so Pages stays current:

```bash
python tools/fetch_products.py
```

It writes `js/products.js`, the matching `assets/products/snapshot.json` that the worker falls back to, and `assets/products/NN-<id>.jpg`, and deletes thumbnails whose products have dropped out of the newest eight.

`.github/workflows/products.yml` runs it every day at 06:43 UTC and pushes the result, and that push republishes GitHub Pages. To pick up a drop immediately, run the workflow from Actions → Refresh products, or run the command above and commit. The Freebuff deployment reads the live listing, so it does not wait for any of this.

## Layout

The layout is a single composition, not a desktop one plus a mobile one: everything inside the orbit is sized from `--size`, so the page scales continuously at any window size without breakpoints. `--size` is set by `js/main.js`, which measures the friends row, the Instagram mark, the credit chip and the legal strip and picks the largest ring whose cards clear all four with a 12px margin — the products stay as big as the window allows and never touch anything. The CSS `--size` formula is the fallback when JavaScript is off. The friends row sits along the top-left edge at every size; friends, their usernames and their shop links live in the `friends` block of `index.html`.

## Friends row

The four creators in "Shop my friends" come from IMVU's public user lookup (`https://api.imvu.com/user/user-<id>`). Each row carries the creator's numeric IMVU id in `data-imvu-id`; ids never change, so a rename is followed rather than lost. That endpoint sends no `Access-Control-Allow-Origin` header, so the browser cannot call it from the page; the usernames, shop links and portraits are shipped with the site instead and kept current by a scheduled job.

On Freebuff, `sites/worker.js` also exposes a same-origin `GET /api/friends?ids=…` route that proxies IMVU's lookup, and `js/main.js` calls it on load, so a renamed avatar or a new profile picture is live on the next visit. When that response lands, a small "updated" chip (`.friends__flag`) fades in just after the heading and fades out six seconds later, so the row never carries a permanent badge. GitHub Pages has no route to call — there the fetch 404s, the committed copy stands and no chip ever shows — and the nightly job keeps that copy current.

`.github/workflows/friends.yml` runs `tools/refresh_friends.py` every day at 06:17 UTC and pushes the result, and that push republishes GitHub Pages. To pick up a change immediately, run it by hand:

```bash
pip install pillow
python tools/refresh_friends.py
```

It rewrites each row's username and `manufacturers_id` shop link inside the friends block of `index.html`, and `assets/friends/<id>.webp` (160px square). `assets/friends/manifest.json` remembers the source picture for each portrait so an unchanged one is never re-encoded. Who is listed is read from the rows themselves: add one `<a class="friend" data-imvu-id="…">` row with its portrait path and the script picks it up.

## Local preview

The page is static — serve the folder and open it:

```bash
python -m http.server 4173
# or
npx serve .
```

Then open <http://localhost:4173>.

## Deploy

`dist/` is the only deploy root. The build script copies the site files into it; nothing else is ever published.

```bash
node sites/build.mjs
npx wrangler dev --config sites/wrangler.jsonc --port 8788   # verify in workerd
```

- **Freebuff Sites** — deploy with `sites/manifest.json` (`assetsDirectory: ../dist`).
- **GitHub Pages** — automatic. Every push to `main` runs `.github/workflows/deploy.yml`, which rebuilds `dist/` and publishes it. No secrets needed; it uses the built-in token. Nightly jobs for friends and products also push refreshed data, which redeploys in the same way.

Asset paths are relative so the same build works at a domain root and under `/choking-lotus/`.

## Rollback

`git tag pre-cleanup` marks the earlier multi-section version of the page (hidden sections, full CSS, nine static cards). To go back:

```bash
git checkout pre-cleanup -- index.html css js assets
```
